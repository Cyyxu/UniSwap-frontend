## 📊 改造对比

### 改造前 ❌
```typescript
// 不安全：Token 存在 localStorage
localStorage.setItem('token', token)
const token = localStorage.getItem('token')

// 问题：
// 1. XSS 攻击可以窃取 Token
// 2. 刷新页面需要重新登录（如果 Token 过期）
// 3. 无自动刷新机制
```

### 改造后 ✅
```typescript
// 安全：Token 存在内存
setAccessToken(token)
const token = getAccessToken()

// 优势：
// 1. XSS 攻击无法窃取内存变量
// 2. Refresh Token 在 HttpOnly Cookie 中，JS 无法读取
// 3. 自动静默刷新，用户无感知
// 4. 刷新页面自动恢复登录
// 5. 并发请求优化
```

## 🔒 安全性提升

### XSS 防护
| 项目 | 改造前 | 改造后 |
|------|--------|--------|
| Access Token 存储 | localStorage（可被 XSS 读取） | 内存变量（无法读取） |
| Refresh Token 存储 | 无 | HttpOnly Cookie（JS 无法读取） |
| Token 泄露风险 | 高 | 低 |
| XSS 攻击影响 | 可窃取 Token | 无法窃取 |

### Token 生命周期
| Token 类型 | 有效期 | 存储位置 | 用途 |
|-----------|--------|----------|------|
| Access Token | 15-30 分钟 | 内存变量 | API 请求认证 |
| Refresh Token | 7-30 天 | HttpOnly Cookie | 刷新 Access Token |

## 📈 性能优化

### 请求队列机制
```typescript
// 并发请求时只刷新一次
let isRefreshing = false
let requestsQueue = []

// 第一个请求触发刷新
if (!isRefreshing) {
  isRefreshing = true
  // 刷新 Token
}

// 其他请求进入队列等待
requestsQueue.push(callback)

// 刷新成功后批量执行
requestsQueue.forEach(callback => callback(newToken))
```
